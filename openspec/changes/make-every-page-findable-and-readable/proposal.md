# Make every page findable and readable

> **Status:** approved — 2026-09-06, owner

## Why

Since `serve-the-docs-from-our-own-server` the documentation site *is* the public homepage at
`stratara.tech`, and an audit of the built output on 2026-09-06 found that the site is well written
and badly announced. The content is in order — 502 documentation tests pass, `docfx build
--warningsAsErrors` reports nothing, all 50 external links answer, the package list matches the 25
packable projects, and the benchmark figures on the landing page match the methodology page. What is
missing is everything a machine reads: there is no `sitemap.xml`, no `robots.txt`, no canonical URL
on any of the 525 pages, no Open Graph or Twitter card, no structured data, and 53 of the 60
hand-written pages ship the same global meta description.

Two of the findings are not SEO but accessibility, and both are WCAG 2.2 Level A: `<html>` carries no
`lang` attribute (3.1.1), and there is no skip link past the navigation (2.4.1). A framework whose
landing page argues for provable properties should not fail the two checks that any automated audit
runs first.

There is also a defect that only shows up when you try to fix the descriptions. DocFX's master layout
emits the global `<meta name="description">` and the page-level one *unconditionally, both*, so the
two legal pages serve two description tags today and all 60 would the moment per-page descriptions
are added. The fix for the descriptions and the fix for canonical, Open Graph, the skip link and the
navigation labels are therefore one fix: the site needs its own copy of that layout.

No framework behaviour changes. No published package changes. Nothing a consumer of a NuGet package
can observe changes.

## What Changes

- **Two DocFX configuration switches**, both verified against a scratch build on 2026-09-06:
  `_lang: "en"` in `globalMetadata` puts `lang="en"` on every page, and a `sitemap` block emits a
  `sitemap.xml` with 517 absolute URLs and `lastmod` on each.
- **A `robots.txt`** served from the site root, naming the sitemap. Unlike `llms.txt`, which lives at
  the repository root and is copied by the workflow, this one lives under `docs/` and is declared as
  a DocFX resource — so a local build produces it too.
- **A forked master layout** at `docs/templates/stratara/layout/_master.tmpl`, copied from DocFX
  2.78.5's `modern` template, adding: `<link rel="canonical">` built from `_appBaseUrl` and `_path`;
  Open Graph and Twitter card tags; a skip link as the first focusable element; `aria-label` on the
  three unlabelled `<nav>` landmarks; and a page-description tag that falls back to the global one
  rather than joining it.
- **`docfx` pinned to `2.78.5`** in `deploy-site.yml`, which installs the latest release today. With
  a forked layout in the tree an unpinned tool is how the fork silently diverges from the template it
  was taken from.
- **Per-page meta descriptions** for the 51 pages that carry only the global fallback, written by
  hand as front matter, one sentence naming what that page answers.
- **JSON-LD structured data** — a `SoftwareApplication` on the landing page naming Stratara, its MIT
  licence, its .NET 10 requirement and its author, who is already named in the imprint, and a
  `TechArticle` on every other page built from the title and description that page now carries. Not
  `BreadcrumbList`: DocFX fills the breadcrumb in the browser from `toc.json`, so the titles it needs
  do not exist at build time.
- **An Open Graph cover image**, 1200×630, generated by a script under `scripts/` from the wordmark
  and the brand blue so that it is reproducible rather than a hand-made artefact, and usable as the
  repository's social preview.
- **Landing-page heading order repaired** — today it runs `h1 → h3` in the "New to the terms?"
  section and `h2 → h4` under "What is in the box" — and `aria-hidden="true"` on the three decorative
  Bootstrap icons.
- **Tests in `Stratara.Documentation.Tests`** for the invariants this change introduces, so they
  cannot rot: every hand-written page carries its own description, no page carries two, the forked
  layout names the DocFX version it was taken from and that version is the one the workflow pins.

**Not in scope.** The DocFX search index, a redesign of any page, translating anything, and the
remaining contrast question — none. Contrast was measured during the audit and passes AA everywhere:
4.86:1 for the brand blue on white, 4.97:1 for its dark-theme counterpart, and 6.76:1 to 9.53:1 for
the body text set at `opacity` between 0.75 and 0.85.

## Capabilities

### New Capabilities

None. This is a documentation and site-infrastructure arc; `skip_specs: true` is set in
`.openspec.yaml`. Specs describe what a consumer of a published package observes, and how the
documentation site announces itself to a crawler is not that.

### Modified Capabilities

None.

## Impact

**Changed:**

- `docs/docfx.json` — `globalMetadata._lang`, a new `build.sitemap` block, `robots.txt` added to the
  resource list.
- `.github/workflows/deploy-site.yml` — the `docfx` install pins `--version 2.78.5`.
- `docs/index.md` — heading levels in two sections, `aria-hidden` on three icons, the JSON-LD block,
  and a `title` that no longer repeats `_appTitle` almost verbatim.
- The 50 hand-written pages under `docs/concepts/`, `docs/getting-started/`, `docs/guides/`,
  `docs/overview/`, `docs/reference/` and `docs/samples/` that have no front matter today — each
  gains `title` and `description`.
- `docs/legal/imprint.md` and `docs/legal/privacy.md` — unchanged in content; they are the two pages
  that already carry a description and therefore the two that serve it twice today.
- `tests/Stratara.Documentation.Tests/` — new tests, listed in tasks.md.

**Added:**

- `docs/templates/stratara/layout/_master.tmpl` — the forked layout.
- `docs/robots.txt` — served from the site root as a DocFX resource.
- `docs/assets/og-cover.svg`, the editable master of the cover image.
- `docs/assets/og-cover.png`, generated from it, and `scripts/refresh-og-cover.sh`.

**Retired by this change:** nothing. No file, workflow or document is superseded.

**Inherited risk, stated plainly.** A forked layout does not inherit DocFX's own improvements. The
pin, the provenance comment in the file's header and the test that ties the two together are what
turn a future DocFX upgrade into a deliberate act with a visible diff rather than a silent
divergence. That is the cost of the five findings that have no configuration switch, and it was
accepted by the owner on 2026-09-06 with the alternatives — configuration only, or a post-build
injection step — on the table.
